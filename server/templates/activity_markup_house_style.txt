\section{Learning Objectives}
\text{Students will be able to:}
\begin{itemize}
\item Explain the key concept in plain language
\item Predict the behavior of a short program
\item Apply the concept in a small coding task
\end{itemize}

\section{Exploration}
\questiongroup{Predict and observe}
\question{Read the C++ example below. Predict what it prints before you run it.}
\info{question,6}{Read the code carefully before answering.}
\cpp
#include <iostream>
int main() {
  int x = 10;
  std::cout << x << "\\n";
  return 0;
}
\endcpp
\textresponse{2}
\info{textresponse,8}{The active student types here.}
\sampleresponses{It prints 10.}
\feedbackprompt{Look for a prediction tied to the code.}
\info{aifeedback,8}{Use the AI feedback to revise your answer before continuing.}
\endquestion
\endquestiongroup

Rules illustrated above:
- Learning Objectives is usually structural, not interactive.
- Put learning-objective bullets in \text plus \begin{itemize} ... \end{itemize}.
- Only include \info blocks if the creator explicitly asks for them.
- If you use \info, only use these targets: questiongroup, question, textresponse, coderesponse, submitbutton, and aifeedback.
- Do not invent new \info targets such as instructor.
- If you include runnable C++ code, wrap it in \cpp ... \endcpp.
- If you include runnable Python code, wrap it in \python ... \endpython.
- If you include remote Python code that should run on the server, wrap it in \pythonremote ... \endpythonremote.
- If you only want to show example code without making it runnable or editable, use \pythondisplay ... \endpythondisplay or \cppdisplay ... \endcppdisplay.
- If you include turtle code, always wrap it in \pythonturtle ... \endpythonturtle.
- If you include runnable turtle code, prefer omitting the timeout unless a specific non-default limit is required. Use \pythonturtle{WxH} ... \endpythonturtle when only dimensions matter, or \pythonturtle ... \endpythonturtle if defaults are fine.
- If you include multiple-choice questions, use \multiplechoice{answer} only for questions with a correct answer, and use \multiplechoice{} for survey/opinion questions with no correct answer.
- Use \responsemode{answer} for ordinary questions and \responsemode{questions} when the student should write questions instead of answers.
- `\responsemode{answer}` is the default for legacy content, but include it explicitly in new questions when practical.
- For `\mode{playground}`, create an experimentation-first activity for instructor demonstration and student exploration. Playground work should be saved and revisitable.
- For `\mode{demo}`, create a temporary demo-style activity for short-lived conference or showcase sessions.
- For `\mode{assignment}`, create a project-style lab assignment with milestone steps and a final assembled solution. Assignment drafts are usually sectionless unless the creator explicitly asks for sections.
- In test mode, include an explicit \score{points,type} rubric block for every question so grading is unambiguous. Use only `response`, `code`, and `output` as score types.
- Never invent a fake answer value for a survey multiple-choice question just to satisfy the parser.
- Do not paste raw code directly into question text.
- Keep all interactive questions inside \questiongroup blocks.
